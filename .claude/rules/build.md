# Web build, exports, CI

- **Never modify anything in `exports/`** (build outputs). Reading the Godot export templates in `~/.local/share/godot/export_templates` is fine.
- **The web build is a PWA** (manifest, icons, offline cache through Godot's service worker). Godot pastes the project name unescaped into the worker's JS string, so `project.godot` has `config/name.web` with a **curly** apostrophe: a straight one breaks the worker. Godot's page registers the worker only when threads are missing, so the Web preset's `html/head_include` registers it. Cross-origin isolation headers are off because the build has no threads. The game asks for persistent storage at start.
- **Build stamp.** `BuildInfo` reads a gitignored `scripts/core/build_stamp.gd` written by `tools/stamp_version.sh`, together with a `.uid` holding a fixed UID (a random one per build would make exports differ, which breaks reproducible builds); `tools/export.sh "<preset>" <out> [--debug]` stamps, exports and deletes the stamp again. The editor binary never has one, so the bots can't pick up a stale stamp (tests set `BuildInfo.test_stamp`). The game never runs git. The commit gets a `-dirty` suffix when tracked files have changes (`git diff HEAD`); untracked files don't count. The title screen shows only the part of version and commit that is known, nothing when neither is. CI stamps before importing and checks out with full history (`fetch-depth: 0`) so the tags exist.
- **CI** (`.github/`): every push runs lint, mapgen, the balance smoke test and one job per bot, and no failure is allowed. Pushes to other branches run them on Godot's stock engine; `main`, pull requests and tags on the **stripped engine** (Godot built with the cuts in `build_conf/`), which is also what every export and the Pages build ship. Exports and the Pages deploy don't wait for the bots. A `v*` tag also makes a GitHub release (`build.yml` job `release`, after every export and the bots) with only release builds (Android release is exported only on a tag, and left unsigned: see the next point), titled with the tag's message, so tag annotated: `git tag -a v0.1.0 -m "Release v0.1.0"`. The stripped templates are cached per platform and kind; a change to `build_conf/` or `.github/scripts/build-stripped-template.sh` rebuilds them (hours). The scripts CI runs are in `.github/scripts/`. The editor that exports is always the stock one, in `build.yml` the release of the template's Godot tag. CI's Android builds (debug and release) are made the way `fdroid.yaml` makes F-Droid's, so the APKs can match it (reproducible builds): the template built with the distribution's OpenJDK 21 (`/usr/lib/jvm/java-21-openjdk-amd64`, as in `fdroid.yaml`) and the NDK Godot pins, exported with the unsigned `F-Droid` preset (its custom template `./android_<kind>.apk`), run through fdroid.yaml's postbuild (`strip-nondeterminism`, since Godot dates every zip entry with the export time, and reproducible-apk-tools' `zipalign.py` at the srclib's tag, with `SOURCE_DATE_EPOCH` the commit's time as on F-Droid's build server), then debug signed with a throwaway key; release stays unsigned (`.github/scripts/export-stripped.sh`). A change to one side of that is made on the other too. `balance.yml` is manual. CI fetches Godot from the pinned version in the workflows; the sandbox uses the copy in `bin/`.
- **Fixed IDs for reproducible exports.** Every scene, resource and script has its UID in git (`uid=` in a scene's header, `.gd.uid` beside a script) and every scene node a `unique_id=`: Godot invents a random one at each export for anything without, and the APKs stop matching F-Droid's. The editor writes them on save; a hand-written scene needs them. `tests/lint.sh` checks it.
- **Android release signing is by hand; the release key never goes to GitHub** (the user's choice; no secrets). The tag's CI run leaves the artifact `velirons-outpost-android-release` (`velirons-outpost-unsigned.apk`); the user signs it locally with `apksigner` and attaches it to the GitHub release as `velirons-outpost-v<X.Y.Z>.apk`, the name `fdroid.yaml`'s `Binaries:` fetches, soon after tagging. `tools/release.sh` prints these steps.
- **Stripped engine cuts.** A class or module turned off in `build_conf/` fails only at runtime, and only on the stripped engine: the local bots (stock binary) don't see it, CI on `main` and pull requests does. After using a new engine class, check it isn't cut there. The stripped builds are CI-only.
- Exports need the Godot export templates; Android also needs the SDK and a keystore. Presets are in `export_presets.cfg`. Every preset but Linux leaves out `tests/` and `tools/` (no game code uses them) with the "customized" resource mode (`customized_files`, those two folders set to "remove"), never `exclude_filter`: Godot applies that filter by erasing from a set that moves its last entry into each hole, in the folder order the disk happens to list, so the packed `uid_cache.bin` comes out in a machine-dependent order and the APK isn't reproducible. Linux keeps them because CI's stripped bots run from its exported pack.
- Release exports behave differently from the editor binary in a few ways (see the BOM note in gdscript-gotchas); check a release export when file reading differs.
- The game log file is not written on the web; a debug build keeps it in memory (`GameLog.web_lines`) and the Debug page's *Download game log* button saves it.
