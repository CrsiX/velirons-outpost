- The title backdrop's maps are baked into `data/title_maps/` (`BakedMap`). After changing the map generator or the scenes' map type / seed, rebake: `gd --headless --path . res://tools/bake_title_maps.tscn` (title_bot fails while they are stale). Tools that need autoloads must be run as a scene, not with `-s`.
- Calling a lambda whose captured object was freed is an engine error ("Lambda capture at index 0 was freed"), even if it checks `is_instance_valid` first, and so is `has()` on a typed array with a freed object. In the bots, wait on something that may be freed with `wait_until(when_gone(x, ...))` (bot_base: holds a weak reference), and compare instance ids. A bot that fails to parse hangs until its timeout: lint doesn't see warnings-as-errors, so run the bot.
- A lambda can't assign the caller's local variables (they are captured by value): let it fill an Array or Dictionary the caller holds.
- Warnings are errors here (a variable inferred from a Variant, a local shadowing a signal such as `changed`, a coroutine called without `await`): give the type, rename, `await` in plain `if` branches.
- In an exported game a BOM in a string literal (`"\uFEFF"`, or the raw character) comes out empty, so `begins_with` it is always true: test a code point instead (`MapJson.without_bom`: `text.unicode_at(0) == 0xFEFF`), build one with `String.chr(0xFEFF)`. The bots run in the editor binary and don't see this; check a release export (`--export-release` into the scratchpad, an autoload probe) when file reading behaves differently there.
- Writing into a packed array held inside an Array or Dictionary (`arr[i][k] = x`) can copy the whole packed array: fill a local one and store it once.

**Gotchas learned the hard way:**
- Game speed is `Engine.time_scale` (speed 0 pauses the tree instead and leaves `time_scale` as it was). Code that must run in real time (UI, `train_pause`, the title backdrop's clock and tweens) divides delta by `maxf(Engine.time_scale, 0.001)` or uses `set_ignore_time_scale(true)`. Anything that changes `time_scale` must reset it to 1 on exit.
- Web input: Godot's web build makes `InputEventMouseMotion` out of every `pointermove`, fingers too, with `relative` taken from `movementX/Y`. Firefox reports that wrongly for touch, so never pan or drag by `relative`; use position differences (see `camera_controller.gd`). Touch also arrives as ScreenTouch/ScreenDrag.
- Stretch: `canvas_items`, aspect `expand`, base 1280×720; `Layout` switches `content_scale_size` for portrait. A SubViewport shown in the UI must be sized by the final transform's scale or it is blurry (see `TitleBackdrop._fit`).
- Assigning a filtered array to a typed array fails at runtime; use `typed.assign(arr.filter(...))`.
- In tests, `await` every coroutine helper, and keep waits shorter than whatever frees the game (the title backdrop swaps games every `duration`).
- Monster-camp guards are enemies too (`CampBehavior`): filter them out when counting a wave's enemies.
- A finished building may be devastated (`Building.devastated`, docs/siege-design.md): "does its job" is `working()`, not `complete`. `level` lives on `Building` (towers, barracks, gates, walls).
- In the bots, "real seconds" are frame time (`get_process_delta_time() / Engine.time_scale`), as the game counts them (`train_pause`), never the wall clock (`Time.get_ticks_msec`): headless frames come much faster than real time.
- A fixed offset from the village centre can land in a clearing the woods close in (rat_bot's map has one east of the village): a bot that puts someone out there picks a tile the village can walk to (`find_spot`, rat_bot's `reachable_near`). And keep the other villagers home when a test needs one particular target (a raider hunts anyone outside).
- Machine-dependent timing checks in the bots (title_bot's frame times) are skipped when the env variable `CI` is set; CI sets `CI=true`, and so should local runs here (`export CI=true`).
- `game.gd` modes: `tutorial_mode`, `scenario` (a campaign scenario: `ScenarioRunner`, its own rules, no saving), `backdrop` (title background game: no raids, no defeat, no input, no HUD), `networked`. A new game-wide rule may need to respect all of them. A game can also be `loaded` (from a save, `Game.restoring` while it is built). A game ends through `Game.end_game(title, sub, won)`.
- New durable state (a field that must survive a load) needs a line in `SaveGame.capture` and its `_restore_*`; save_bot's round trip (save, load, save again: the same body) catches most misses. Changing the body's layout means `SaveGame.FORMAT` + 1 (old saves are then refused, not migrated).

**Known, not yet looked into:** app start-up spends most of its time compiling the scripts (loading `net.gd` pulls in the whole class graph); the web build has no threads (`variant/thread_support=false`).

# The game

A dark-fantasy isometric village-defense game made with Godot 4.7 (GL Compatibility renderer). It targets Web, Linux, Android and Windows and works with mouse, keyboard or touch.

The last outpost of the kingdom of Veliron sits in the middle of a generated 75×75 map of forests, meadows, heath, steppe, swamps, lakes, rivers and mountains, sometimes by the sea or next to a volcano. Goblins and skeletons come down the winding roads from the map edge towards the village gates. Villagers build, farm and scout on their own. You decide *where* things get built and *who* mans the towers.

## Rules (iteration 2)

| Resource | Used for | Comes from |
|---|---|---|
| Gold coins | Buying and upgrading military units, the Spatial Archmage | Kills (`gold_on_kill`, paid instantly), corpses brought home by gatherers (`gold_on_collect`), calling waves early, start |
| Food | Recruiting civilians and feeding them (upkeep per villager) | Farms worked by farmers |
| Building material | Watchtowers, farms, worker camps, light stones, rebuilding huts | Foresters chopping trees; buying it with gold (tap the material counter) |

- **Village:** a walled 5×5 block near the centre of the map (co-op: near the centre of its player's slice), laid out as in the spec (`TWGWT`): 9 huts, walls, 4 gates and 4 corner wall towers. Each intact hut houses one civilian, so the huts set the population cap. Walls, gates and wall towers have HP and hold enemies back (see **Building HP and sieges**).
- **Civilians** are recruited with food. You start with one builder, one farmer, one forester and one explorer. A farm and a worker camp stand near the village for free from the start, and the farmer and forester work there (`START_BUILDINGS`). The map keeps no room for them: each goes on the nearest free spot within `START_BUILDING_RADIUS` of the centre, and where none fits (a farm among ash, sand, swamp or trees) the village starts without it.
  - **Workers are assigned automatically.** A villager whose role works at a building (`works_at` in `CIVILIANS`: farmer at a farm, forester at a worker camp) goes straight to a finished one nobody works at, the one nearest the village first. A newly finished farm or camp takes an idle worker of that role. You can still unassign and assign by hand in the building's panel.
  - **Builder:** walks to the next construction site, builds it, walks home, rests, repeats. Hut rebuilds come before every other job whenever a builder (or the hero in Build mode) picks a new one, also after fleeing; work under way isn't dropped for them.
  - **Farmer:** works one farm. They fetch its stored food, carry it home (also when they flee), rest, repeat.
  - **Explorer:** clears the fog on their own (not part of the starting villagers when the whole map is revealed from the start or the fog is off). They head for the nearest fog and push deeper, return to closer fog instead of wandering far off, and avoid areas other explorers are covering and the guards of monster camps (fog by a camp waits until it is cleared; so does fog they fled from guards on the way to, while those guards live: `EXPLORER_BLOCKED_RADIUS`; the hero exploring too). Fog over forest, rock or water they can't walk into is looked into from its edge.
  - **Forester:** works from one worker camp. They walk from the camp to the nearest tree, chop for a while, walk back (each return pays a little building material; a forester who flees delivers his load at home), rest, and go back to the same tree until it falls. The tile then becomes meadow, and they move on to the next tree. Chop time per tree type is `TREE_CHOP_TIME`. Very rarely, a tree wakes up as a *wrathwood* at the first blow (see Enemies).
  - **Gatherer:** stays in the village until enemies have died, then walks out for their corpses. It only goes for "safe" corpses (no living enemy nearby) on land its village has explored (none in the black fog) and carries up to `GATHERER_CAPACITY` per trip. Back home each corpse pays `gold_on_collect` and `food_on_collect`.
  - **Every civilian** runs home when they spot an enemy outside the walls, then rests before going back to work. Inside the walls is safe while no enemy has broken in: nobody there flees or can be hurt, so builders go on rebuilding huts during an attack. Once an enemy is inside (`Siege.breached`), villagers walking in there are exposed (at home they stay safe). Villagers have HP (`CIVILIAN_HP`): any enemy that gets at one hurts them (they never fight back), at 0 HP they die, and at home they heal (`CIVILIAN_REGEN`).
  - **Miner:** unlocked for everyone once anyone walks up to a mine. Works one mine for gold (`MINE_GOLD_RATE`), safe inside; one miner per mine, the first to arrive. Lives in a hut (and dies with it) but stays at the mine.
  - **Spatial Archmage:** can't be recruited: a level 10 spatial mage becomes one (see Military units). Decoration for now ("coming soon"); not listed in the Village tab.
- **The world** (docs/world-design.md; everything in `config.gd`):
  - *Map types:* Temperate, Highlands, Coast, Desert, Volcanic or Random, and an optional seed: in the single-player menu and the lobby (host). The settings dialog shows the map's type and seed.
  - *Zones:* meadow (farms more than half on meadow +20 % food), oak woods, pine forest, heath, steppe (no farms), swamp (walking ×0.7 off the roads, so enemies are never slowed; no farms) and ash land around volcanoes (no farms). Map files may also have the campaign's city (cobblestones; its mountain tiles are houses; no farms; never generated). Trees are forest tiles that block building and walking.
  - *Water:* lakes, rivers and coasts. Deep water and lava can't be crossed; shallow water can, at ×0.5. Roads cross rivers on bridges (their look depends on the zone) and shallow water at fords. A farm next to water gets +10 % food. On Coast maps every village gets an inlet from the sea reaching to 8 tiles from its walls; on other types a village may get a lagoon (the type's `"lagoon"` chance); either gets a landing road. Water spawns (`MapData.water_spawns`) mark where water monsters come from (docs/world-design.md §9.8).
  - *Mountains and volcanoes:* impassable; roads go around them or through passes. Nothing is built near a crater.
  - *Roads:* the only way enemies travel. Single player: 3-5 from the map edge to the gates (an extra one where needed for at least 2 approaches). Co-op: every village is linked to at least two others (one with two players) and has its own spawns on its slice's stretch of the map edge.
- **Special objects** (hidden in the fog until found; finding one is logged, Info):
  - *Treasures:* the hero loots them in Explore mode, first come first served, and carries the loot home. Downed on the way, or switched to another mode, she drops it where she is: the hero or a gatherer can pick it up later. Some hold a *relic* (a small permanent bonus).
  - *Monster camps* guard every far treasure (at least one per village) and half of the middle ones. The hero attacks one only on your order (the camp's panel: *Attack with the hero*). Whoever flees from a camp's guards (an explorer, any villager, the hero) uncovers the camp for their village, so it can be attacked (`CAMP_REVEAL`). Towers and barracks fight any guard in their range without an order, so building next to a camp wears it down. Hurt monsters don't heal.
  - *Unit-unlock sites:* the summoner (stone circle, from wave 3), the apprentice (mage's tower, from wave 5) and the acolyte (ruined chapel, from wave 6, 16-24 tiles out) have to be unlocked: the hero visits the awakened site, and the unit is unlocked for every village.
  - *Ruined watchtowers:* the hero claims them (Explore mode, before new land); restoring one is an order: it becomes a devastated watchtower of that village, repaired by a builder for half a watchtower's cost. A map file may also hold a ruined barracks (2x2; scenario 3), restored the same way into barracks.
  - *Mines* at the foot of mountain ranges, with a road; *monster lairs*, each with a winding road to the network. From wave 10 they wake up one by one (per village area, the next every 3 waves) and add a spawn point for their village's wave share (no extra enemies), themed by lair (a crypt sends skeletons, necromancers and vampires); the hero can clear one for loot, and it sleeps 3 waves.
  - The hero's Explore mode: claims first, then unguarded loot, then unknown land.

- **Buildings:** go on explored open land outside the walls: not on trees, water, lava or mountains, nor next to a volcano's crater. Farms can't go in steppe, swamp or ash land.
  - *Watchtower* (1×1): holds one military unit. Watchtowers and light stones block their tile, so they need a free tile next to them that can be reached from the village; placing one where trees cut off every side is refused. Builders and units always use the nearest side they can actually reach.
  - *Farm* (3×3): one farmer.
  - *Worker camp* (1×1 tent): one forester.
  - *Training grounds* (2×2 yard with a hut, weapon racks and archery targets; materials and gold): two slots, one military unit (stationed like on a tower, but it doesn't fight there) and the hero. See **Hero** below.
  - *Barracks* (2×2 yard with benches, food and drink, and a straw puppet full of arrows; materials and gold): 1 bench at level 1, up to 3 at level 3 (`BARRACKS_LEVELS`). Upgrades are done by a builder and add a bench and activation range. When an enemy comes within range (shown as a circle when it is selected), everyone on a bench turns out and fights: they step down from their bench (`Soldier.Mode.LEAVE`) and walk back onto it (`SEAT`) once no enemy is left. Units heal on the benches, with their HP bar shown until healed. The panel has a line and actions for each bench.
  - *Light stone* (1×1 rune pillar): gives vision on its own, no one can be stationed in it (`LIGHTSTONE_SIGHT`). Destroyed huts can be rebuilt on their ruined lot (40 material).
  - **Cancel:** a construction site, an ordered upgrade or repair, or a hut rebuild can be cancelled from its panel. The refund is the paid cost × (1 − progress), rounded down (`Building.cancel_refund`); the panel says how much, or "Too far along" when nothing comes back. A cancelled hut rebuild goes back to a ruin.
  - **Tear down:** every building placed outside the walls (also the starting farm and camp; not huts or wall towers) has *Tear down* as the last action of its panel. It stops working at once: units on it or marching to it walk back to the reserve (downed ones revive there), its worker is freed and takes a vacant workplace of that kind if there is one, and an ordered upgrade is cancelled (refunded like a cancel). A builder (or the hero in Build mode) comes like to a construction site and needs `TEARDOWN_TIME_SHARE` (half) of its build time; the bar counts down. Then it's gone and `TEARDOWN_REFUND` (33 %) of the building material spent on it (list price plus paid upgrades, rounded down; a restored ruined tower counts its full list price) comes back. *Stop tear-down* in the panel spares it; units stay in the reserve.
- **Building HP and sieges** (docs/siege-design.md; `BUILDING_HP`, `SIEGE`, `scripts/systems/siege.gd`):
  - Every building has HP (gate 80/160/320, wall 100/200/400, wall tower 200/400/800 by level; watchtower 100/200/400, barracks 150/250/400, farm 100, camp 50, light stone 80, training grounds 150; hut 1). It never heals by itself.
  - At 0 HP it is **devastated**: it does nothing (units walk back to the reserve, its worker is freed, an ordered upgrade is refunded, no sight), shows its ruin (walls, gates, towers) or rubble, and walls / towers no longer block their tile.
  - **Repair** (panel, `repair` command): building material only, `REPAIR_SHARE` (half) of the material spent on it (price plus upgrades; village pieces count `PIECE_PRICES`) × the missing HP share, rounded up; a builder (or the hero in Build mode) takes `REPAIR_TIME_SHARE` × build time × that share. It gives back the HP paid for. Cancelling refunds like a site. Huts are rebuilt all or nothing for half their price (80 → 40). Tear-down refunds are scaled by the HP share.
  - **Gates and walls** level up to 3 (`PIECE_LEVELS`, the `upgrade_tower` command): more HP, a new look. Every upgrade adds the max HP's growth to the current HP.
  - **Enemies breaking in:** near their village (`SIEGE.approach` tiles round its pieces) ground enemies leave their road and follow the village's siege field (a 4-connected Dijkstra field towards its intact huts in which an intact gate / wall / wall tower costs its HP, `hp_per_step`) to the cheapest way in. They hit the barrier in their way (`damage` × `siege`; witches cast at it), but melee foes come first; they leave a barrier only for a way `switch_margin` steps cheaper. Through, an enemy walks to the nearest intact hut and burns it. A broken corner tower leads nowhere while both its walls stand. Kinds with `siege` 0 (necromancer, siren) wait and slip past after `stuck_slip` (45 s). Rats and thieves (`"entry": "slip"`) are held `slip_time` (4 s) by an intact gate, then get through unharmed. Flyers fly over walls and gates. The octopus's idle arms smash buildings within reach.
- **Towers** (the 4 wall towers and every watchtower) start at level 1 and can be upgraded to level 3 for building material (`TOWER_LEVELS`).
  - A builder walks over and does the work; the tower keeps fighting meanwhile.
  - Levels add range for the stationed unit, and HP.
  - Each level adds decorations: crimson banners and shields at level 2, gold trim and a lit brazier or lantern at level 3.
  - The tower panel shows the level and HP and offers *Upgrade tower*, *Repair* (when hurt), *Upgrade <unit>...* and *Withdraw*.
- **Military units** are bought with gold in the Army tab and wait in its reserve. The summoner, the apprentice and the acolyte first have to be unlocked on the map (see Special objects). Every kind is stationed on a tower (drag a card onto a tower, or tap a card and then the tower).
  - **Stationed units** can be tapped right on their tower to select them (panel with Upgrade and Withdraw). Drag one off its tower to move it: while dragging, the unit follows the pointer, every free tower or training grounds lights up, the one under the pointer turns green, and a dashed arrow runs from the old post. Drop it on a free post and it walks straight over. Drop it on another unit and the two swap posts if each fits the other's post (archer on a tower and acolyte in barracks: yes; shield bearer in barracks and healing mage on a tower: no; never a unit out on a sortie); while a drop would swap, two curved arrows run back and forth between them. Drop it on the sidebar (or the bottom bar in portrait) to withdraw it. Anywhere else, nothing happens.
  - Units **walk** from the village to the tower, and back when withdrawn. They only reappear in the reserve once home, so towers can't be re-staffed instantly.
  - Units go up to **level 10** (stat curves in `MILITARY`, level 1 and level 10 values). They are upgraded with gold in a dialog (Army tab, a tower's or a bench's panel). From level 3 the dialog also offers the kind's **specialisations**, each starting again at level 1 (the tech tree is in docs/military-design.md); turning into one refills its HP, and a unit out on a sortie changes its look at once. Upgrading a level 3 base unit into a level 1 specialisation never lowers HP or DPS, and level 10 of a specialisation is stronger than its base unit's (see the standing rule above). Its single hits may be smaller (Swiftbowman). Training at the grounds only levels units up.
  - Units have **HP**. On towers they can't be hurt; outside (walking, on a barracks sortie) they can. At 0 HP a unit is **downed**. After a revive time that grows with its level (`UNIT_REVIVE_TIME`) it is back: on its bench if it belongs to barracks, otherwise in the reserve (shown dimmed with a countdown; nothing can be done with it meanwhile). Units heal on benches and while unused in the reserve (`UNIT_REGEN`). Out in the field, ranged units use their own range, which is shorter than any tower's and never upgraded.
  - *Archer:* shoots the enemy closest to its gate. Becomes a *Crossbowman* (slow, heavy bolts, more range) or a *Swiftbowman* (a hail of light arrows).
  - *Shield Bearer:* barracks only; lots of HP, little damage, holds enemies up. Becomes (all barracks only, 100 gold; docs/military-design.md §3a):
    - *Warrior*: the most HP (90 → 300). Out on a sortie he shouts a **war cry** at once and every 10 s (`cry_interval`): every ally within 2.5 tiles (`cry_radius`; units out, tower units, summons, heroes, himself, any village) is hasted by `cry` +10 % → +50 % for `cry_time` 3 → 5 s, i.e. all its attack, cast, summon and heal timers run 1 + `cry` times as fast (`Combat.haste`; timers tick `delta * rate`). One haste per unit: an equal or stronger cry refills it, a weaker one counts only once it has run out (`Combat.war_cry`). A red-orange shout ring, and chevrons over hasted units (`UnitFx` CRY; not on co-op clients).
    - *Berserker*: archer DPS at full HP. **Rage**: strike interval × (1 − `rage` × share of HP lost), `rage` 0.3 → 0.8 (at level 10 with 10 % HP 3.6× as fast). **Lifesteal** below 50 % HP (`lifesteal_below`): 10 % → 25 % of the HP its blows really take (`Combat._lifesteal`; a per-stat curve, `"curves": {"lifesteal": 1.5}`). Redder as it loses HP.
    - *Halberdier*: archer DPS, reach 1.2 (`range` on a melee unit), and it goes for flyers (`hits_flyers`, `MilitaryUnit.hits_flyers()`): barracks with one turn out for flyers. The bane of riders: ×2.5 to a mount (`vs_mounted`, never to the rider on foot), and it breaks charges (`breaks_charge`: no charge bonus on it; its blow halts a mount 0.5 s and spends its charge; `Combat.hit`).
  - *Summoner:* while enemies are within the tower's range or sight, summons earth elementals next to the tower, up to a cap. Upgrades shorten the interval, raise the cap, and make newly summoned elementals stronger (existing ones keep their stats). From barracks it steps outside and summons there, where enemies can attack it; it has no attack of its own. Becomes a *Fire Summoner*: hovering fire elementals with less HP, more speed and much more damage, which burn themselves with every hit. Or a *Druid* (docs/military-design.md §3b): **thornlings**, slow and tough with less damage, whose every blow **roots** the enemy (`Enemy.root`: it can't walk but fights on) for 0.6 → 1.2 s; then it can't be rooted for 2 s (`SUMMONS.thorn.root_immunity`); flyers can't be rooted.
  - *Apprentice:* whirling dark-blue orbs. Becomes a *Fire Mage* (exploding fireballs that splash), an *Ice Mage* (slows its target, more with levels), a *Healing Mage* (no damage; heals units and heroes of every village nearby, not summons: in a tower as far as the tower reaches, so tower upgrades widen it; elsewhere within its own `radius`) or a *Spatial Mage* (throws its target back along its road). A level 10 spatial mage can become the **Spatial Archmage** (`ARCHMAGE_COST`, a free hut, after a confirmation). This civilian replaces the archmage, who can no longer be recruited.
  - *Acolyte* (50 gold; docs/acolyte-design.md): holy damage, a thin golden beam straight down onto the enemy (instant, burst "holy_beam"). Archer HP, a little less DPS, much shorter field range (1.6). Prays (hands folded); a soft pulsing light behind it everywhere it is shown (`glow`), arms raised for a moment when it casts (`cast_art`). Becomes:
    - *Inquisitor*: holy melee (cross and warhammer, a flash of holy light per blow), barracks or training grounds only. An acolyte that turns into one on a tower (or on its way) walks back into the reserve. Targets by effective distance (`hunt`): witches −4 tiles within 7, the unholy −2 within 5, others as they are; it leaves its fight only for a target at least `hunt_switch` (1) better.
    - *High Priest*: support, no attack but a weak melee counter-strike when hit on a sortie. Its aura (on a tower as far as the tower reaches, out of barracks only on a sortie within its own 2.6; not on the bench, the training grounds or walking) gives every allied unit, tower unit, hero and summon +2 % → +20 % damage (`aura`; the strongest aura counts, no stacking, no range), shows a tiny still halo over their heads, makes necromancers raise ×2 slower (`necro_slow`), and is the hook for revealing invisible enemies (`Combat.in_holy_aura`).
- **Earth elementals** wander near their tower until they spot an enemy, then fight it in close combat. Enemies fight back and are held up while they do. A level-1 earth elemental is exactly as strong as a goblin on Normal (difficulty scales goblins, not elementals). Elemental speed is `SUMMONS[kind].speed` (tiles/s); their HP and damage are the summoner's `summon_hp` / `summon_damage` times the kind's factor. Elementals leave no corpse, and they crumble when their summoner is withdrawn, downed or specialised, or back on its bench after a sortie.
- **Hero** (`HERO` in `config.gd`): half villager, half soldier, with a sword. She starts in the village centre. She has no hut, eats nothing and doesn't count as a villager. The top-bar button shows her XP, has her health bar along its bottom (green from 50 %, yellow from 20 %, red below; empty while downed) and opens her panel: the title names her mode with its icon ("Hero: defending"), then level, HP and XP, one icon button per mode (the current one framed; Support only in co-op, with its village toggle under it), *Level up*, what she is doing, and *Go to hero*. Mode icons: a shield (Defend), a crossed hammer and saw (Build), a globe (Explore), a wheelbarrow with bones (Gather), a straw training dummy (Train), "Zzz" (Rest), a handshake (Support). Modes:
  - *Defend* (default): waits in the centre. When an enemy comes within `alert_radius` of the village's walls (or gets inside) she goes out to fight it, then re-targets: inside the walls first, then the nearest, the strongest among equals. She doesn't chase beyond `leash` from the centre (unless another mode took her out there: then she fights what is within her sight on her way back). Enemies fight back, and a witch's spells hurt her.
  - *Build / Explore / Gather:* the villager jobs, done a little less well (half build speed, a smaller reveal radius, 2 corpses per trip). In these modes she runs from enemies like a villager. A mode change takes effect at once wherever she is, also while she flees: switched to Defend she stops and fights (or walks back, fighting what comes her way); only a switch to another of these three with an enemy still close keeps her running. Switched to one of them out in the field with nothing to do, she walks back to the centre. Her sword's cooldown runs in every mode and no switch resets it (no extra blows from switching). In *Explore* she first claims unlock sites and ruined watchtowers, then loots unguarded treasures, and only then explores unknown land (see Special objects).
  - *Attack a camp:* ordered from a monster camp's panel, whatever her mode; she goes back to her mode once it's cleared. Any mode button (her current one too) cancels the order; a camp whose monsters she can't get at she gives up after `camp_give_up` (3 s).
  - *Train:* needs training grounds with a unit stationed there that isn't at max level. She walks over and passes her XP on to it (`train_rate` per second). When the unit has `train_xp` for its next level it levels up for free, no gold. After each level-up she pauses for `train_pause` (4 real seconds, whatever the game speed; the log and her panel say so), so you can change her mode and keep the rest of her XP. The XP needed grows by level and difficulty (`TRAIN_XP_DIFFICULTY`). The panel shows the XP needed, the progress and the XP she has left. Without such grounds she defends instead, and drops any fight as soon as a unit becomes ready. A gold upgrade resets the unit's training progress.
  - *Rest:* walks back to the village centre and stays there without fighting.
  - *Support* (co-op only): defends another village (see Co-op rules).
  - **Healing:** whenever she idles in the village centre, in any mode, she gets HP back: `rest_regen` (3 HP/s) after `rest_delay` (3 s), up to her max HP.
  - **Levels:** she spends her own XP on levels in her panel (*Level up*): up to level 20 (`HERO_MAX_LEVEL`), each level costing more XP (`HERO_LEVELS`), for more HP and a harder sword. Three glowing green chevrons rise over her head when she levels up.
  - **XP:** 2 per sword hit, plus 10 more for the blow that kills an enemy; 1 per second of building, per exploring step that uncovers fog, per unlock site and per claimed ruin; 4 per corpse picked up; 10 per treasure looted (not for picking up dropped loot again) (`HERO_XP_PER_ACTION`, "kill" is the bonus). Training earns none, and no other unit ever gains XP.
  - **Downed:** at 0 HP she loses all XP (never her levels), leaves no corpse, and revives in the centre with full HP when the wave is over (downed between waves: when the next one begins), still in the same mode.
- **Fog of war** has three states:
  - *unexplored*: black;
  - *explored*: darkened, terrain known, enemies **not** visible;
  - *under surveillance*: clear. That's within 4 tiles of every hut, 3 tiles of every gate and every other finished building, near villagers or soldiers outside the walls, and within the range of **manned** towers (all set in `config.gd`).
  - Every unit of yours outside (villagers at work, the hero in any mode, soldiers, summons, caravans) also explores the fog close around it (`UNIT_REVEAL`, 1.8 tiles); the hero earns XP for it as for exploring. Only explorers and the hero in Explore mode go looking for fog.
  
  Enemies can sneak up on the village unless towers watch the approach. During the first 5 waves on Easy and Normal (not Hard), and in any wave in which a lair just woke, a soft red warning light marks where each hidden enemy's road enters watched land (`WARNING_LIGHT_WAVES`).
- **Waves:** wave 1 starts 90 s after the level begins (`FIRST_WAVE_DELAY` in `config.gd`). Every later wave starts 30 s after the last enemy of the previous one is gone. "Call now" skips the wait for bonus gold. Waves are endless and escalate: 4 + 2 per wave enemies (rat packs on top), each wave's HP ×`WAVE_HP_GROWTH` (1.12) over the last; damage, speed and loot don't grow. The top bar shows the number of enemies on the map plus those still to come this wave.
- **Corpses:** a killed enemy leaves a corpse where it fell. Corpses rot after `CORPSE_LIFETIME`, and every corpse of wave N disappears once wave N+1 is finished. On deep water a corpse sinks (`AQUA.sink_time`) and nobody can gather it. Corpses left lying at a wave's start draw vultures, which eat them (see Enemies).
- **Enemies** (all defined in `ENEMIES` in `config.gd`, one documented entry each; `WAVE_MIX` says who joins from which wave). In melee they lunge at what they fight and sway back.
  - *Goblin:* the basic attacker; breaks gates and walls. Gold on kill, gold and a little food as a corpse.
  - *Skeleton:* goblin stats, no food. From wave 2.
  - *Ork:* slower, tougher and hits much harder. Gold only on kill, lots of food as a corpse. From wave 3.
  - *Witch:* frail, no melee. Rich gold on kill, no gold and little food as a corpse. From wave 5.
    - She stops at any manned tower within 3.6 tiles (a level 1 watchtower's range, so towers can always hit back) and casts a whirling pink bolt that bewitches its unit: no shooting, summoning or healing for 45% of her spell cooldown (0.9 s). A pink glow marks the bewitched unit.
    - Military units outside (walking, or out of a barracks, even a summoner that never attacks her) are targets too: her bolts hurt them.
    - Her spells damage earth elementals. Whoever attacks her becomes her first target.
    - She counts her casts per target: after `spell_ignore_after` (20) casts she ignores that target, until it attacks her again (which resets its count). So she can't stall a wave in front of a tower that can't reach her, or a summoner's tower.
    - Existing elementals are not affected by the enchantment.
  - *Rat:* in packs of 4-7 (`RAT_PACKS`, from wave 3), frail but growing with the waves, faster than anything, a little space between them (fire mages love them). Rats burn no huts: a rat that gets through a gate eats max(5, 5 %) of the village's food and is gone. On the road they look for a working farm within 6 tiles and go there: it grows nothing while rats are on it, and each rat eats its stored food. They go for villagers and units within 2.5 tiles and bite them in reach (very little damage). Once a farm is empty and has grown nothing for 15 s, each rat on it gives it up for good (50 % chance every second) and walks on to the next farm or the gate, so an empty decoy farm only holds them up briefly. A rat on a farm leaves after 30 s without being attacked, with no corpse and no gold; once the rest of the wave is gone, any rats left vanish within 30 s (`RAT_WAVE_LINGER`). Killed: a little gold, no corpse. The hero in Defend mode goes for rats on her village's farms when nothing else is near a gate, and barracks send their units to farms within twice their range when nothing else is in range (`BARRACKS_FARM_RANGE_FACTOR`).
  - *Thief* (from wave 7): a goblin's strength, quicker. Where its village has a guild warehouse (scenario 4) it goes for that instead (plunders it, steals and runs). At a gate it burns nothing: it steals max(a random number from the wave to twice the wave, 4 % of the gold), never more than there is, and runs back to where it came from with a sack of coins. If it gets away, the gold is gone. Killed: a little gold at once, and its corpse holds its own value plus everything it stole (no food).
  - *Gargoyle* (from wave 10, grey stone): the first **flyer**. It keeps to the roads but no swamp or ford slows it, and it is drawn bobbing with beating wings over its shadow. It fights like a goblin (with twice its HP and harder, slower blows), but only ranged attacks (towers, archers, mages, including slows and pushes), fire elementals (flyers too) and halberdiers can go for it. Other ground melee units (the hero, shield bearers, earth elementals) only hit back when it hits them and their blow is ready (a counter-strike); barracks whose units can't reach flyers don't turn out for it. As slow as an ork. Kill: gold; corpse: food only.
  - *Necromancer* (from wave 13): no attack. When the corpse of another enemy lies within 3 tiles, it stops and channels on it (a green beam) for 5 s (`cast_time`); then the corpse rises again as its old kind with half its HP, draining to 0 over 20 s, and the necromancer walks on for at least that long before its next spell. A corpse gone mid-spell ends it. While a fighter of any village is near (the hero, a soldier or an elemental within 3 tiles, or a manned tower that has it in range; a Healing Mage or High Priest, who can't hurt it, doesn't count) it doesn't walk on: it stays and waits for its next raise. A raised enemy killed pays half its kind's kill gold (rounded down), a decayed one nothing, and neither leaves a corpse. The first raise per village and game is logged. Kill: a lot of gold; its corpse yields nothing and can't be raised. Between skeleton and ork in speed, goblin HP. It takes 1.5 x holy damage, and everything it raised takes 2 x (on top of its kind's own factor).
  - *Vampire* (from wave 13): a ground unit, slower than a goblin, twice its HP, a goblin's blows. Takes 0.67 x magical damage. Of the HP it really takes from whatever it hits (villagers, units, the hero, summons) it gets 67 % back, never above its max. Once, the moment its HP would drop below a third (even to 0: it is never killed in one blow, a raised vampire neither), it keeps a third of its HP and turns into a bat for 10 s in a puff of dark smoke: it flies over every ground unit (only ranged attacks and fire elementals reach it), fast, and doesn't bite. A bat that reaches a gate does no harm: it gains a third of its max HP (never above its max) and flies back the way it came. When it lands, the vampire walks to the village again; only on its feet does it break in and burn a hut. Kill: 6 gold; corpse: 8 gold, no food. A necromancer can raise it once.
  - *Slime* (from wave 4, `slime3`/`slime2`/`slime1`, one kind per size): a slain slime splits into `split_count` (2) of the next size down; the smallest just dies. Each size has twice the HP and damage of the one below. A spawned slime rolls a pastel colour (`SLIME_COLORS`) that its halves keep. No corpses (nothing to gather or raise). At a gate the big one burns a hut; the smaller ones only with their `raid_chance` (25 %, 10 %), else they melt away. One library entry ("Slime").
  - *Spider mother* (from wave 9, at most 2 per wave, one more every 5 waves (`max_count_every`, `Config.wave_max_count`); hollow-tree lairs too; Wilderness; docs/enemies-design.md §15b): bigger and tougher than an ork (90 HP), slower (0.6), fights like one. On her way she lays a clutch of 4-6 eggs (`Waves.lay_eggs`) without stopping: the first once she is within 7 tiles of a manned tower or barracks of ours whose units fight (`lay_near`, a little more than a level 3 wall tower's range) or is first alarmed, then every 15 s (`lay_every`), at most 5 clutches in all (`max_clutches`, alarm clutches included). Alarmed (a fighter of ours within 4 tiles, a manned tower with her in range, or hurt) while fewer than 3 of her young are within 2.5 tiles, she stops, lays a clutch and waits until it has hatched or is smashed, still fighting; then not again for 12 s. Kill: 10 gold; corpse: 8 gold, no food. Raised by a necromancer she lays a clutch at once and then every 15 s, **undead** eggs (`Enemy.undead`: unholy, ×2 holy, no drain), whose spiderlings are undead too.
    - *Spider egg* (`spider_egg`, `"library": false`): always 1 HP (`fixed_hp`), never moves, counts for the wave; wobbles for its last 2.5 s and hatches after 6 s into a spiderling (`Waves.hatch`), leaving a broken shell for 4 s (`Enemy.hatch_out`: out of the `enemies` group). Towers, soldiers, elementals and the hero go for eggs only when nothing else is in reach (`"low_priority"`, `Enemy.LOW_PRIORITY_TILES`). Villagers don't run from eggs (`"scares": false`), only from what hatches. No gold, no corpse.
    - *Spiderling*: about a rat's strength, speed 1.8, fights like a goblin and breaks gates and walls, but burns no huts (`raid_chance` 0: it "scuttled off", the kind's `"gone"`). 1 gold, no corpse.
  - **Wolves and riders** (docs/enemies-design.md §15e; `ENEMIES.wolf`, `goblin_raider`, `horse`, `legion_cavalry`, `MOUNTED`; `Enemy.mount` + `MountedBehavior`, `FleeBehavior`):
    - *Wolf* (from wave 5, an animal: holy ×1): faster than a goblin, weaker; comes in **packs** of 2-3 (`"pack"`, `Waves._pack_up`: a share's wolves grouped, each pack from one spawn; a lone one gets a second). Breaks gates weakly (`siege` 0.5). Through a gate (`"raid": "maul"`, `Game._maul`) it kills the villager of the hut it got to (else the nearest lived-in one); the hut stands; it is gone. Kill 2 gold; corpse 3 food, no gold. Raised: an undead wolf.
    - **Mounts:** a mounted kind has `"mount"` (the animal: its corpse and resist), `"mount_hp"` and `"rider"`; a scenario can put any enemy on a horse (a queue entry's `"mount"`, `"mount_hp"`: art `unit_<art>_mounted`). While mounted every hit lands on the mount (`Enemy.mount_hp`, scaled like HP; a brown bar under the rider's), none carries over. When it falls (`Enemy.dismount`, `Waves.mount_fell`): the mounted kind's kill gold, a kill of that kind, the animal's corpse; a kind with a `"rider"` turns into it in place (new number, HP, speed, behavior, look; same wave and target), anyone else goes on on foot (`on_dismount`, logged for the named).
    - **Riding** (`MountedBehavior`): mounted it never hits a gate or wall, and its ways never cross an intact one (`open_way`): by road to its village, then it **circles** it (`ring` 3 outside the walls, from `approach` 5); once the village is breached (the siege field's way in crosses no intact barrier) it **rides in** like the others (`Enemy.ride_in`) and burns a hut; it **hunts** within `hunt_radius` 5 (`"hunts"`: "all" anyone outside, villagers too; "melee" melee fighters only), giving up beyond `chase` 8; Legion riders (`"escort"`) keep within `escort_radius` of the nearest Legion soldier on foot. After `circle_time` (40 s) at the village without a blow it rides to the nearest gate and gets off (the mount runs off: no corpse, no gold) and breaks in on foot. **Charge:** after `charge_distance` (3) tiles ridden without a fight (`Enemy.charge_ready`, dust, a lean) its next blow does ×2 (`charge_x`), not on a halberdier.
    - *Goblin raider* (from wave 7, alone; half the ork's share, no cap): a goblin on a wolf (mount 18 HP, 1.6 tiles/s); hunts anything. Unhorsed: a goblin.
    - *Horse* (`horse`): there is no living one, only a fallen mount's corpse (8 food, no gold). Raised it is an **undead horse** (`FleeBehavior`): never fights, bolts to the quietest spot near it, dies of the drain; counts for the wave.
    - *Legion cavalry* (campaign only): a footman on a horse (mount 45 HP); escorts and hunts melee fighters; unhorsed, a footman.
  - **Water monsters** (docs/aquatic-design.md; `"habitat"`): they join a village's waves only where water lets them reach it (`Aqua.eligibility`: a fitting body of deep water within reach of the land round the village; water-bound ones only where a level 3 watchtower could cover it), coming from its water spawns (amphibians half the time from the edge). On deep water they dive (`Enemy.dive`; untargetable while diving, down or surfacing; shots in flight fizzle, splash skips them); a bridge is road and water at once: they pass under it staying under (`Enemy.must_be_under`), and over deep water it joins the bodies on both sides; melee reaches a monster on deep water only from the tile beside it (`melee_ok`, `melee_reach`). A corpse on deep water sinks in 6 s. The first of each kind per game is logged. When only water monsters are left of a wave: if they are all water-bound (leviathan, octopus), none named or on a post, and none has been in a fight (hurt, blasting, an arm out: `AquaBehavior.engaged`) for 3 s (`AQUA.leave_after`), they go back into the deep (no corpse, no gold) and the wave can end; otherwise, after 15 s (`AQUA.warn_after`) the log and a toast say so, once per wave (the wave still ends only when they are dead).
    - *Crab* (wave 6, amphibian): a goblin that swims (roads and water; under on deep water by itself).
    - *Siren* (wave 8, amphibian): holds back and sings: our mobile people are pulled towards her (`Unit.force_move`), every unit's timers slow (`Combat.song_rate`); melee can't strike her in water except from a High Priest's aura, which also shields from the song. Out of patience (30 s luring nobody, or 60 s of holding in all: `max_hold`) she walks to the gate.
    - *Leviathan* (wave 10, at most 2, deep water only): surfaces near our people and channels a water blast (range 4.6: only level 3 watchtowers and wall towers outrange it); comes up every 20 s anyway.
    - *Gigantic octopus* (wave 20, 25 % of waves, one at most, deep water only): 8 arms (`octopus_arm` enemies, HP growing with the waves) grab our people and drag them into deep water, where they drown; cut an arm to free them. An arm with nobody in reach smashes a building of ours within reach (not huts).
  - *Wrathwood* (Wilderness, very rare, never in a wave; docs/enemies-design.md §15c; `ENEMIES.wrathwood`, `WRATHWOOD`, `Wrathwoods` + `WrathwoodBehavior`): from wave 8, a tree may wake at a forester's first blow on it (oak 1.5 %, pine 0.3 %, dead trees never; +0.05 % per tree that village's foresters felled, "the forest remembers", at most 3 %; one per village at a time, none for 3 waves after one died; never in the tutorial or the title backdrop). It shudders as its tree for 3 s, then chases the forester (walking over forest too, `Pathing.wood_path`), then smashes his worker camp, wanders 20 s, walks home and guards its old tile for good (territory 4, leash 6). Swing-by blows at whatever is in reach while it moves (buildings ×3, never huts); whoever hurts it while it wanders, goes home or guards becomes its foe. Heals 4 % of max HP/s near trees (×2 for 10 s back home); every 8 s its roots hold everyone of ours within 1.6 tiles in place for 2 s. 220 HP (wave-scaled), slow; fire ×2, projectile ×0.5. Kill: 35 gold; its corpse is a log of living wood (40 building material, no gold or food, can't be raised). It counts for no wave (`Enemy.wild`, like camp guards) and is saved with its state.
  - *Vulture* (Wilderness, animals; docs/enemies-design.md §15d; `ENEMIES.vulture`, `VULTURES`, `VultureBehavior` + `VulturePack`): carrion birds for the corpses left lying. At a wave's start, on top of its mix (`Waves._vulture_packs`), from wave 6 (`Scenario.vultures_from_wave`: scenario 6 from wave 4), one pack of 2-4 per 5 edible corpses nearest the village, at most 3 packs; they count for the wave. Each pack has a target corpse and comes from the map edge nearest it by flight; they fly their own way (`Pathing.sky_path`: walkable tiles, forest and deep water, never mountains, buildings or solid objects), land on it (`Enemy.landed`: melee reaches them then) and eat for 4 s; after each meal the corpse is gone with 50 %, and each meal adds 25 % HP and damage (at most 4: twice as strong, `Enemy.fed`). Target gone: the nearest corpse; none: they search 10 s, then fly to the nearest edge and vanish once out of sight 3 s (they never have to be killed). They fight only for themselves and their corpse (hurt in the field, they turn on the attacker; hurt by a tower, that bird flees out of range for 8 s); never at a gate. They eat the campaign's fallen (lost, like risen ones), never a vulture's corpse or the wrathwood's log. Kill: 2 gold; corpse: 3 food, no gold; a necromancer can raise one.
  - Together, the special kinds make up at most about `WAVE_MIX_CAP` (85 %) of a wave: the shares are capped first, then each kind is rounded and gets at least 1, so a wave can end up a little above (86-88 %).
- **Damage categories:** every hit is exactly one of *melee* (the hero's sword, shield bearers, earth elementals, enemy blows), *projectile* (arrows and bolts), *magical* (mage orbs, frost, warp, the witch, the leviathan), *fire* (fireballs and their splash, fire elementals), *holy* (the acolyte line) or *pure* (a raised enemy's drain; never scaled). Enemies can resist or be weak to a category (`resist`, e.g. the vampire's magic and fire 0.67, the water monsters' fire 0.5, the wrathwood's fire 2 and projectile 0.5). Holy factors: goblin, ork, thief, gargoyle, the spiders ×0.75; skeleton ×1.25; necromancer and vampire (bat too) ×1.5; others ×1; anything raised or undead ×2 on top (`raised_holy`). `"unholy": true` marks skeleton, necromancer, vampire (and raised and undead enemies count as unholy: `Enemy.is_unholy`).
  - Difficulty scales strength and loot values (`DIFFICULTY_SCALED`), never cooldowns or ranges.
- **Huts:** every villager lives in exactly one hut, so the number of intact huts caps the population.
- **Raids:** each enemy that gets into the village burns the nearest intact hut, on every difficulty (except rats, thieves, vampire bats, small slimes, spiderlings and wolves, as described under each; riders get in mounted only through a breach). Only the villager living there dies; empty huts cost no lives.
- **Starvation:** while food is at 0, a random villager starves every 15 s.
- **Defeat:** when no civilians or no intact huts remain.

## Title screen
The game opens on a title screen with **Campaign**, **Singleplayer**, **Multiplayer**, **Tutorial**, **Library**, **Map Editor** and **Exit**, each with an icon (Exit is hidden in the browser).
- *Campaign* (docs/scenarios-design.md §7) lists the built scenarios (so far 1 *Homecoming*, 2 *The Old Friend*, 3 *The Wardline*, 4 *The Split*, 5 *The Betrayal*, 6 *The Dead*, 7 *The Exile*, 8 *The Pale Court*, 9 *The Drowned Abbey*, 10 *The Last Wardline*, 11 *The Crown*: the whole campaign). A scenario is a single-player game with its own map file, village, rules, waves and story: an in-engine intro cutscene (dialogue boxes with portraits, skippable), teaching cards and one-time hints on a card top left with the scenario's objectives under them, and an outro once every objective is met (then the win screen: **Next scenario** (a play arrow, `icon_next`) on top, which starts the next scenario whether it was completed or not (`Game.play_next_scenario`); after the last one **Show campaign map** (`icon_campaign`; `Settings.campaign_next` opens the title on it); under it *Main menu* and *Play again*). It can't be saved. Each scenario is one file, `scripts/scenarios/scenario_<n>.gd` (a `Scenario`), listed in `Campaign.SCENARIOS`; `ScenarioRunner` plays it.
  - *The campaign map* (`CampaignMap`, docs/ui-design.md): *Campaign* opens an old fantasy map of Veliron filling the screen (art `campaign_map`, drawn by `gen_art.py` from `data/campaign_map.json`: the places, road crossings and roads; the geography is docs/story-design.md §4a: ocean west, wilderness north beyond the Wardline, Karmere north-east, Lyrenne east and south-east, Aurelith south). Each scenario names its place (`Scenario.place`, `Campaign.places()`: the outpost holds 1, 2, 3 and 10, the capital 8 and 11) and a portrait (`Scenario.portrait`). Pins (`pin_<symbol>`); Brenna's route along the roads (`Campaign.route`, the same smoothing as the picture: a red dotted trail where done, red dashes ahead; the stretch to the next scenario draws itself in); places not open yet not shown at all; a wax seal (`map_seal`) on finished ones; the next one pulsing. Choosing a place glides the map to it; the map can be dragged. A parchment scroll (landscape: on the right; portrait: a bottom sheet) lists the place's scenarios with the chosen one's portrait, line and Play. Arrows step, Enter plays, Esc rolls the scroll up, then closes the map.
  - *Progress* (`Campaign.completed` / `complete`, `user://campaign.json`: `format`, `campaign` (the titles in order), `completed` (titles)): a won scenario is remembered by its title. Completed ones carry a check on the card, the next (after the highest completed) is where the card opens. Release builds open only unlocked scenarios (`Campaign.unlocked`: the first, one after a completed one, or one before a completed one); debug builds open all.
  - *Scenario 1, Homecoming:* Brenna Hale (the hero, named; `Hero.given_name`) wakes by her tent on the north road and walks home to a ruined village (4 of 9 huts, most gates, walls and wall towers devastated); her father Einar is the forester (`Civilian.given_name`). Archers only, no specialising, no barracks or training grounds; enemies weaker than Easy (`Settings.enemy_scale`); five scripted waves (`Waves.scripted`, `last_wave`); any villager's death is a defeat. Objectives: survive the waves, rebuild every hut, gate, wall and wall tower, more villagers than at the start, food not falling. The outro brings Pell up the road. Its map is `data/maps/homecoming.json` (made by `tools/make_scenario_map.gd`, meant to be edited by hand in the map editor).
  - *Scenario 2, The Old Friend* (same map): Pell Dunmore (a named villager, the **merchant**: `Merchant`, can't be recruited) arrives; the player places his **trade stall** (`stall`, `Stall`, 2x2, campaign-only: `"campaign": true` in `BUILDINGS`, only buildable where a scenario lists it; its level is its stage, `STALL_LEVELS`: peddler, stall, guild market). While Pell tends it, gold buys lots of material or food from its goods (the `trade` command); the goods refill slowly; rats eat them (`Stall` extends `Farm`). Wave 1 waits until the stall stands; seven waves; talks between waves (`play_scene`); Pell must not die (`must_live`), nor his stall (once it stood, devastated or torn down loses). Cards: stall, the hero claims the ruin, restore it, trade (waits, `"ready"` / `"wait_title"`, until wave 2 is over and there are goods), a hero level, barracks with a shield bearer, a tower upgrade. Optional objectives: buy something, the walls hold. Pell's guild is the **Silver Thread Merchant Guild** (short: Silver Thread Guild; the neutral one, with no alliances; the guilds that chose sides call it the Leftovers).
  - Journal pages (`Journal`, scenarios 3 and 5) pause the game and grey it behind them, like the settings.
  - Cutscenes can hold a **choice** (a line with buttons; Skip jumps to it, never past it: `Cutscene`, `"choices"`).
  - *Scenario 4, The Split* (`data/maps/guildtown.json`, a Coast map with the village on a sea inlet): away from home, so Brenna can't be revived (`hero_revives` false: downed is a defeat). The Silver Thread Guild's town: Wenna (the **guild master**, `GuildMaster`, can't be recruited; she stays in her hut, which looks like a guild house: `Scenario.homes`, `Hut.look`), Pell's Guild Market, and the **guild warehouse** (`warehouse`, `Warehouse`, 2x2, campaign-only, prebuilt by the harbour: `"near_water"`) that only thieves go for (`ThiefBehavior`: along their road, then across to it; they plunder it, `Config.WAREHOUSE`, and run off with gold; the monsters go for the huts; 500 HP, ten plunders, and it can't be repaired); if it falls the scenario is lost (`must_stand`). Nine big waves (about 2.5 x a home wave) with thieves, twice as many once the foreign coins are found (after wave 6), crabs and one siren out of the sea only (`Scenario.amphibians_from_water`); the rival master's offer (a choice: taking the gold loses); foreign coins; Pell and Wenna must not die.
  - *Scenario 5, The Betrayal* (`data/maps/old_fort.json`, laid out by `tools/citadel_map.gd`, not generated): a mountain range across the map with one pass, the fort filling it (two walls across the pass from mountain to mountain, the gates at level 2 (`Scenario.piece_levels`), the road bending through both gates; inside 4 huts in two rows of two, a dried-up well (decor `well_dry`, also in the editor: `Config.EXTRA_DECOR`), one dead tree, two barracks and training grounds, empty: buildings may go inside, `Scenario.build_inside`); forest and the monster camps north, meadow and steppe south; roads and enemies from both sides. Only Brenna and Pell come (his stall outside the south gate; the merchant and residents can't retire). Sigmund camps in the south (`SIGMUND_TENT`): found, the waves start and he joins as a builder (`ScenarioRunner.join_villager`; huts full: a builder makes room, else the objective "Give Sigmund a roof over his head" appears (`"shown"`) until the player retires someone) and tells what happened; three pieces of evidence (two guarded in the north, one in the south; hidden, unmarked; journal pages, the game grey behind them); a hollow-tree lair in the north wakes at wave 6, or at once when found; ten waves with witches and gargoyles; in the last the first **Dread Legion** (`legion_footman`, `legion_captain`: campaign-only enemies, released when they fall, no corpse; captains never die: below 30 % they fall back off the map, `CaptainBehavior`, `Enemy.retreating`) comes down the pass with the named captains Lysa and Torben on horses (`Enemy.set_identity`: a name over the head, their own art; `"mount"`: docs/enemies-design.md §15e), added to the running wave (`ScenarioRunner.add_enemies`, `Waves.add_to_wave`), with gargoyles from the rocks above the pass.
  - *Scenario 6, The Dead* (`data/maps/battlefield.json`, Desert): the plain where the armies met. 36 of the **fallen** lie on the field (`Corpse.fallen`: corpses of kind skeleton with their own look that never rot or clear; raised, a skeleton); gatherers carry them, one per trip (`Config.FALLEN`), to the **graveyard** by the chapel (`graveyard`, `Graveyard`, 3x3, campaign-only, prebuilt `near_site`) and bury them (`GatherJob` `TO_GRAVE` / `BURYING`); bury 24 before too many rise (lost when too few are left). Anselm the priest stays in his house (`Resident`, roles `priest` / `princess`; `GuildMaster` is one too). The chapel is awake from the start (`Scenario.sites`): Brenna wakes it, acolytes. Undead waves with necromancers from wave 3, repeating until enough are buried. Pell and Anselm must not die.
  - *Scenario 7, The Exile* (`data/maps/refuge.json`, Temperate): Fiona's refuge. Brenna lives at her tent outside the walls (`Scenario.hero_lives_out`, `Hero.home_override` / `home()`) until Fiona lets her in after wave 2 (`ScenarioRunner.hero_moves_in`); Fiona's trust locks commands in steps (`Scenario.command_error`: until wave 2 no building, repairs or villager orders, only units; after wave 7 new buildings). The **druids** (the summoner's druid branch; these take no orders: `MilitaryUnit.bound` from a prebuilt unit's `"fixed"`, `MilitaryUnit.fixed()`) sit in their **grove** by the stone circle (`grove`, `Grove`, a barracks); in wave 5 a band comes for it and a druid downed then is a defeat. The mage's tower opens after wave 2, the stone circle after wave 5 (`ScenarioRunner.awaken_site`); acolytes from the start (`Scenario.unlocked`). Twelve waves; Pell and Fiona must not die.
  - *Scenario 8, The Pale Court* (`data/maps/pale_court.json`, Volcanic): no army, only Brenna's band in the reserve (`Scenario.reserve`; `Scenario.recruiting` false: nobody can be recruited, gold only levels and specialises). Three **crypts** (monster lairs set by the scenario: `Scenario.lairs`, their waking wave, guards and kinds; cleared for good) wake at waves 1, 4 and 7 and are spawn points of its waves (`"lairs": true`); the hero clears them (*Attack with the hero*). More **Dread Legion** kinds: the archer (shoots our people in the open, `LegionArcherBehavior`), the guardsman (half damage from arrows), the banner-bearer (Legion soldiers near it strike faster: `Enemy.haste`) and the court champion **Rurik** (cleaves; a killable boss guarding the third crypt, `MonsterCamp.add_guard`), and **Legion cavalry** from wave 6 (`legion_cavalry`, a hint); two **Legion camps** (camps of Legion soldiers) hold the court's gates (optional). Lothar's offer after wave 3 is a choice (taking it loses). Pell must not die.
  - *Scenario 9, The Drowned Abbey* (`data/maps/drowned_abbey.json`, Coast; a road crosses a lake to an island on bridges): the **abbey** (a campaign treasure, `abbey`) holds the First King's Hand (a reward's `"item"`: `Village.items`), held by a vampire camp and **sealed** (`Treasure.sealed`) until wave 6 is over; a **guard octopus** keeps to the water by it (`Enemy.post`, outside the waves). Two unnamed priests stay home (residents). Lysa leads the Legion down the causeway in wave 6, on her horse. Taking the relic raises the **leviathan** (a boss: `"hp_x"`, `"power"` / `Enemy.power` in a queue entry) and the Legion's rest. Pell's boats bring supplies. Objectives: bring the relic home, slay the leviathan, hold 10 waves; Pell must not die.
  - *Scenario 10, The Last Wardline* (the Wardline map): home at its strongest, every Wardline ruin restored and manned at the start (a prebuilt post can be a restored ruin: `"ruin"`); **no revive** even at home; sixteen waves, the Legion from wave 4 by every road. Lothar's demand after wave 3 (a choice: opening the gates loses); Fiona's three mages join after wave 4 (`ScenarioRunner.give_units`); Legion cavalry from wave 5; Torben and Lysa (captains, mounted) lead waves 8 and 12; wave 16 is **Halvard's** (mounted), the Legion's marshal, a **commander** (`legion_marshal`, `CommanderBehavior`: Legion soldiers near him strike faster and take less damage, `Enemy.haste` / `Enemy.guard`; he **rallies** footmen down the roads while he lives; killable). **Guild caravans** (`ScenarioRunner.caravan`, `ScenarioCaravan`: a cart down a road that halts while enemies are near it and pays at the gate) come down the Wardline road at waves 3, 6, 9, 12, 15. Einar is the forester. Pell must not die.
  - *Scenario 11, The Crown* (`data/maps/capital.json`): the capital, a new zone, the **city** (`ZONES.city`, map format 4: cobbles; its mountain tiles are houses, the zone's `"peaks"`; never generated), ash land, a few steppe spots with trees; the **throne hall** (a `landmark` treasure, never looted). No farms: a food cart after every wave and Pell's stall. Fiona at home (must not die), her mages bound on the towers. Twelve waves, Legion cavalry from wave 2; in the last **Rhodri** (`legion_king`: a commander whose blows cleave, `"downed"` at 0 HP: he flees back along his road; he rides out and fights on on foot once his horse falls: two phases) and Lothar (a named champion). Won when wave 12 is over; the outro ends the campaign (the `curse` burst, Fiona's black eyes).
  - *Scenario 3, The Wardline* (`data/maps/wardline.json`, the home map grown to 100x100 by the tool, with ruins along the north road): restore and man the four ruined watchtowers and a ruined **barracks** (ruins can be barracks now: `"building"` in the map file, format version 3) and light the road between them with light stones (what buildings see: `ScenarioRunner.lit`); thieves from wave 3; the waves repeat, growing, until done (`repeat_last`); journal pages and the logbook as parchment popups (`Journal`). Prebuilt posts with units (`Scenario.prebuilt`), specialising and training grounds open.
- *Behind the menu* a real game plays itself in slow motion (`Config.TITLE_BACKDROP`, `scripts/ui/title_backdrop.gd`): scenes one after the other, each a fresh game on a fixed map with fixed posts, units and enemy groups, the camera drifting along its road. The menu shows at once over black; only then is the first scene made, and it fades in. Between scenes it fades to black (at least `black` seconds), makes the next one and fades in. Scenes are quick to make: their map is baked (`BakedMap`, `data/title_maps/`) and the game is built over many short frames (`Game.build_step`, `build_slice`; still and unrendered meanwhile), so the menu stays responsive. It stays until a game starts. No fog, sound, input, raids or defeat.
- *Singleplayer* opens a sub-menu with **Continue** (only when there is a single-player save: the newest, autosave or manual; then Enter's button), **Play**, **Load...** (the save list), **Difficulty**, **Map** (the map type; after Random, *Custom...*: a map file from the map picker, then *Your village: n of m* when it has several), a **seed** field (empty: random; hidden for a map file) and **Back** (Esc goes back too).
- **Map Editor** (docs/map-editor-design.md; `scenes/map_editor.tscn`, `scripts/editor/`): makes, inspects and edits maps of 50-200 tiles (`Config.MAP_SIZES`, villages per size `MAP_SIZE_SLOTS`), isometric or top-down (Tab), with tools for terrain, zones, trees and peaks, decor, beaches, roads (bridges and fords by themselves), volcanoes, villages and their single pieces, spawns, water spawns (deep water only; the inspector names the water body and which water monsters fit), slices and objects (a left click places, a right-click erases that tool's kind, a right drag pans; the first tab, *File*, holds the file operations, Properties, Play and Exit, and with it open a click selects); an inspector (the selection and the tile under the pointer), layers, live checks (errors keep a map from being played; fewer than 2 approaches and a non-standard village layout only warn), undo / redo, and an automatic tidy-up. In landscape the two side panels fold to their edges; in portrait they are a bottom sheet with a handle, as the game's dock. Slices show as 1-8 in the lobby's village colours (stored 0-7). Maps are `.json` files (a canonical, readable format: rows of characters per tile layer; strict export, tolerant import that refuses anything outside the format) in `user://maps` (built-in ones: `res://data/maps`), imported / exported anywhere (a download on the web). *Play* tries the map; the game's settings then offer *Back to editor*. The web build warns before opening a map of 150 or more.
  - A map file can be played in single player and co-op (the host picks it in the lobby, every client gets a copy, the host assigns each player a village). `MapData.for_game` makes the game's map: villages nobody plays become ownerless ruins (huts ruined for good, no owner, their spawns silent, enemies never go there).
- *Multiplayer* (LAN co-op, up to 8 players; docs/multiplayer-design.md):
  - Pick your village's **name** and **colour** (both remembered). Then **Host game**, or join one of the **games found on your network**, or **join by address**.
  - In the **lobby** (two panes: the players on the left; your name and colour, the game's settings and Ready / Start / Leave on the right; stacked in portrait): everyone's village in its colour. Names and colours are unique (taken colours are greyed out), and can be changed until you tick **Ready**. The host picks the difficulty, the map type and seed, and **starts** once everyone is ready; nobody can join after that. A player who dropped can rejoin under the same village name.
  - Or the host picks **Saved game...** (next to Map: a co-op save): the lobby then needs exactly as many players as the save has villages, the host assigns each player a saved village (*Village* buttons), and each village takes its new player's name, keeps its colour and logs "Village X is now played as Y".
  - In the game: every player runs their own village on one shared map, with their own fog. The host simulates; clients send their orders and see only what their village sees (plus every village's huts and name).
  - Only the host sets the speed and can pause ("Paused by the host"). A client's settings dialog doesn't pause, and its *Back to title* is *Leave game*. If the host leaves, the game ends for everyone.
  - **Co-op rules** (docs/multiplayer-design.md):
    - The map grows with the village count (`map_size`); every village gets its own slice of the map with its own stretch of map edge, roads to at least two other villages (one with two), and a ring road round its walls.
    - Every village gets its own wave share, plus an extra of 25 % × villages.
    - A village falls when it has no villagers or no intact huts. Its enemies turn to the nearest standing village, and it stands again once it has a villager in an intact hut. The game is lost when every village has fallen.
    - The other villages' names float over them, and every village has its own fog.
    - **Sending help:**
      - *Send resources* (Village tab) sends gold, food or material by caravan, a horse-drawn cart walking from centre to centre. The sender pays at once; the receiver gets the cargo minus a tax (`help_tax`: 10 % per extra player, at most 50 %). Enemies can't attack caravans.
      - *Send...* (Army tab, next to Upgrade selected) sends a reserve unit. It walks there and can't be recalled; inside the other village's walls it joins that village's army.
      - The hero's *Support* mode sends her to defend another village (a second toggle in her panel picks which). The village she helps can't give her orders. She heals and earns XP there, and when downed revives at home and walks back.
- Difficulty cycles Normal → Hard → Easy. It multiplies enemy strength and loot values (`DIFFICULTY_SCALED`: HP, speed, damage, spell damage, gold and food) per value (`Config.DIFFICULTY_MULTIPLIERS`): by 1.5 on Hard (speed only 1.2) and 0.67 on Easy; whole-number values are rounded, minimum 1 unless they start at 0.
- The defeat screen offers *Try again*, *Load last save* (single player, when the game has a save) and *Main menu*.
- **Saving** (docs/save-design.md): only between waves (no wave running), locally in `user://saves` (`Config.SAVE`). *Save...* in the settings (a name; co-op: the host only; not in the tutorial), and an **autosave** after every wave (one file per game, `Game.game_id`; the newest 5 games' kept). Single-player saves load from Continue / Load... (title, settings), co-op saves only in the lobby. The save list's and the lobby's map preview shows only explored land (`SaveGame.seen`: the village's fog; co-op: all villages' together). A load keeps everything durable (map with felled trees, fog, objects, buildings, villagers, units, hero, corpses, camp guards, statistics, ids); what anything is doing restarts: whoever is out in the field asks once what to do from there (`Civilian.resume_work`: a forester goes on with his tree, a builder to a site...; the hero's job too); units on a sortie are back on their bench. Every view starts on its village. Nothing of a running wave is ever stored: a game left mid-wave goes on from the end of the wave before.
- **Tutorial** (docs/tutorial-design.md) is a guided first game on a fixed map (`Config.TUTORIAL`: Highlands, seed 1337, Easy) with a small village: a builder, a forester and their camp. A card in the top-left corner gives one instruction at a time (13 steps: a welcome with *Let's go* (the sidebar starts folded, so opening it is the first tap), watchtower, archer, farm and farmer, calling a wave, gatherer, the hero exploring and levelling up, barracks and a shield bearer, a unit level, a tower upgrade), and a pulsing outline or a marked spot on the map shows where (with an arrow at the edge of the map area when the spot is off screen or under the top bar or the open dock; a spot built on meanwhile moves to the nearest free one). A step ends when it's done; nothing is blocked meanwhile. While it runs, the waves wait: wave 1 (2 goblins) comes when the player calls it (the gatherer step waits for its first corpse), wave 2 (5 goblins and an ork) when the barracks are manned. Corpses don't rot, and the hero starts resting (she snores: Z's rise from her head whenever she rests). *Play on* (at the end, or after *Skip tutorial*) goes on as a normal game from the next wave; *Back to title* leaves. It can be played again any time (nothing is saved about it). If the village falls, the defeat screen offers *Try the tutorial again*.

**Debug builds** (`OS.is_debug_build()`: a debug export, `--export-debug`, or the game run from the editor or the `godot` binary, so the bots too; never a release export) add *Debug...* to the settings dialog: +1000 gold / food / materials, +1000 XP for the hero, reveal the entire map (all terrain explored, the fog of war stays), unlock all (every unit and role that has to be found), and *Spawn enemy...* (any kind, now, at a random edge spawn of your village, outside the waves' rules: it doesn't start or count for a wave). They are commands (`Commands._debug`), so they work for a co-op client too; a host on a release build refuses them. (There are no debug switches in `config.gd`, and no setting starts a game explored or without fog. `Game.disable_fog` turns the fog off for the title backdrop and tests only.)


## Controls
- Drag the map to pan; scroll, pinch or **+** / **-** to zoom (out to `CAMERA_MIN_ZOOM` 0.22, in to 1.6); WASD or arrow keys pan too (also while paused). Over the sidebar (the bottom sheet in portrait) the wheel only scrolls it, and at its ends does nothing: it never zooms the map there.
- One speed button in the top bar cycles 1× → 2× → 4× → paused. **1** / **2** / **3** set 1× / 2× / 4×. **Space** pauses and, pressed again, goes back to the speed before (to 1× if the game was paused with the button).
- **H** (or *Go to hero* in her panel) moves the view to the hero; while she is down, to where she fell. Held down, H keeps her in the centre of the view until let go. **Z** moves it to the village centre.
- Hero modes by key (`Hud.HERO_MODE_KEYS`): **P** Defend, **B** Build, **E** Explore, **G** Gather, **Y** Train, **R** Rest (a toast says so). **T** opens the statistics.
- **U** opens the selected unit's upgrade dialog (a unit on its post, else the reserve card picked in the Army tab), or upgrades the selected tower, barracks, gate or wall (into the build queue). **Q** repairs the selected building. **R** with a unit selected withdraws it (else the hero rests).
- **Tab / Shift+Tab** select the next / previous unit on a post, clockwise round the village from the north, and centre the view on it. **N** selects the next farm, camp or found mine without its worker (nearest first). **V** opens / closes the villager list. **F1** lists every hotkey (`Hud.KEYS_HELP`: keep it in step with new keys).
- **Esc** closes the newest open popup, like its Close / Cancel (never its OK): the HUD keeps them on a stack (`Hud.register_popup`: placing, the info panel, the hero panel, the villager list, the trade / send / upgrade dialogs, confirmations, settings, the Debug page, the tutorial's skip dialog; the library and statistics close themselves). With none open, Esc pauses and opens the settings; Esc again closes them and the game goes on as before (paused stays paused). Nothing on the game-over screen.
- When something waits in the build queue but nobody can build it (no builder, and the hero is alive but not in Build mode), a red warning says so after 5 s. Both warnings count real seconds, whatever the game speed, and paused time doesn't count.
- When the food has been at 0 with a negative rate (per minute, next to the food) for 5 s, a red **food-shortage** warning shows under it, with a tip by what is missing: no farm → build one; a farm but no farmer → recruit one; a farm without its farmer and a farmer without a farm → assign them; every farm worked → no tip (`Hud.food_warning_text`).
- Gold, food and material brought home float up with their icons ("+2 gold +8 food" as icons).
- The people button in the top bar (villagers / huts) opens the **villager list**: every villager of the village, by role, with what they are doing now (and their HP when hurt) a *View* button that moves the view to them (to the village centre for those at home), and *Retire*: after a confirmation the villager leaves the village for good and their hut is free again (say, an explorer who has nothing left to find). The last villager can't retire. A *Rebuild all huts (n)* button queues every ruined hut. Buttons keep their size and sit centred in their row.
- Buttons that cost something follow the resources while their popup is open (greyed out while too poor, on as soon as enough is earned; `Hud._refresh_dialogs`).
- Costs are shown with icons (gold, food, material), XP with a light-blue star and HP numbers with a heart (in words, "HP" stays a word).
- The Army tab shows the units in stock at the top, the units to recruit below them.
- Tap to select a building (info panel with actions) or to place what you picked in the Build tab. One building per pick: once it's placed, build mode ends. Tapping the picked entry again, the big **✕ Cancel** button in the bottom corner, Esc, right-click or Android's back button put it away.
  - *With a mouse*, the building follows the pointer (green: it can go there, red: it can't) and a click builds it.
  - *With a finger* (no hover), the first tap shows it there with **✓ Build** and **✕** under it (check and cross are icons, `icon_yes` / `icon_no`: mobile browsers lack the characters). Tap Build or the building to build it, or tap elsewhere to move it. Where it can't go, Build is off and the hint says why.
  - *Drag* a Build entry out of the sidebar onto the map and let go to build it there (under a finger it shows a little above it, so the finger doesn't hide it). Let go over the sidebar to put it away; a drag inside the sidebar just scrolls.
- The sidebar can be collapsed for more map on small screens.
- **Portrait and landscape** switch automatically: Android follows the rotation sensor (`display/window/handheld/orientation = sensor`), browsers and desktop windows switch when they get taller than wide. The `Layout` autoload keeps the UI the same physical size in both.
  - *Portrait:* the top bar takes two rows: the wave controls (wave, speed, library, statistics, settings) on top, the resources and hero below. The sidebar becomes a **bottom sheet**: the Build / Village / Army tabs always show along the bottom edge. Tap a tab or the chevron to slide the page up (at most half the screen, `SHEET_MAX`; the entries scroll by finger from anywhere on them, and a scroll never taps a button). Tap the open tab, the chevron or the handle to fold it. Or drag it: the handle, any tab, the gaps between the tabs and the chevron all pull the sheet along with the finger; let go and a flick (`SHEET_FLICK`) or else the nearer end decides. A tap on a tab still only switches the tab.
  - *Camera cutouts:* on a phone the HUD and the map editor keep clear of the front camera or notch (the safe area, `Layout.insets`, read again every `SAFE_AREA_POLL`); the map and full-screen backgrounds still fill the screen (`Layout.inset` / `Layout.bleed`; HUD code mixing screen positions with its own uses `Hud.to_ui`). The browser keeps pages out of cutouts itself.
  - *Full screen:* turned to landscape, a phone or tablet goes full screen: the Android app at once, a mobile browser with the next tap (browsers only allow it then; iOS Safari can't do it for pages). Once per turn to landscape, so leaving full screen sticks until the next turn.
  - The sheet folds away by itself while you place a building, station a unit or drag a unit card, and comes back afterwards. Selecting something folds it too, and the info panel appears just above it.
  - Entries sit in two columns when there's room. The hero panel and the trade dialog open one at a time.
- The window can be resized freely; F11 toggles fullscreen in a game (not on the title screen).
- **Settings** (gear, top right) pauses the game and shows it in grayscale behind the dialog: *Continue* (resumes at the earlier speed; Esc does the same), *Save...* (between waves) and *Load...*, *Log level* (Info / Important / Debug), *Language* (built, but hidden while English is the only language), the map's type and seed (to play it again), and a red *Back to title* (no confirmation).
- **Library** (open book, left of the statistics icon and the gear; on the title screen, the *Library* button): reference pages in tabs, *Enemies*, *Units*, *Buildings* (gates and walls too), *Villagers*, *Hero*, *Places* and *Damage* (every damage category: who deals it, which enemies take more or less), each entry with its picture, a short text and the real numbers, read from `config.gd` (HP, speed, damage, costs, ranges, levels, from which wave). It shows everything, also what hasn't been found yet. In single player it pauses the game, greys it out behind it like the settings, and goes on at the earlier speed when closed (*Close* or Esc); in co-op nobody pauses. Settings, library and statistics behave alike here.
- **Statistics** (bar chart, right of the library; or **T**; docs/statistics-design.md): from wave 2 (`STATS.from_wave`; greyed out before, a tap only says so) and from a *Statistics* button on the game-over screen. Tabs:
  - *Summary:* counters, one column per village (the best in a row marked gold in co-op), in foldable sections Military, Economy, Village, Hero and Co-op (2+ villages). Sub-rows (by kind, source, role) only where something happened.
  - *Timeline:* a line graph of a picked metric (an icon button with the metric's name beside it opens a grid of icons that fits on the screen), sampled every 15 s of game time (`STATS.sample_interval`), with a mark per wave; hover or tap for the values.
  - *Awards:* Deadliest tower, Busiest gatherer, Best explorer, Hero's finest wave, Closest call (fewest intact huts; not the wave the village fell in), Best neighbour (co-op).
  
  `Game.stats` (`Stats`) counts on the host (single player: the game) through hooks in the systems and the `Economy.earned` / `spent` signals (calls that add or spend pass a source / purpose); nothing counts before `Stats.start` (the starting village) or after game over, nor in the title backdrop. It pauses like the library and the settings (not in networked co-op, not after game over), shows the game in grayscale behind it, and goes back to the speed before when closed (paused stays paused). A co-op client asks the host by RPC when it opens the screen (and every 5 s while open); at game over the host sends the numbers to everyone.
- **Event log:** recent game events as plain, see-through text in the bottom left (across the bottom in portrait). Three levels:
  - *Important:* deaths and destroyed huts, with the cause ("farmer 2 died when goblin 4 burned their home").
  - *Info:* waves starting and ending, the hero's return, finished buildings and upgrades, completed training, special objects found, unlocks.
  - *Debug:* every player action and game event.

  The game starts at Info. Everything is kept regardless of the level shown, so changing the level re-filters older messages too. Each level keeps its newest 10 messages, at most 10 are shown, and messages vanish 30 s after they were logged. Everything is numbered per kind for the log ("archer 5", "watchtower 2", "tree 482").

## Roadmap
- Co-op multiplayer (LAN, 1–8 villages on one map): see [docs/multiplayer-design.md](docs/multiplayer-design.md).
- Map editor and map files: built, see [docs/map-editor-design.md](docs/map-editor-design.md); scenarios (start setup, waves, triggers, areas that start explored) come next, in their own files pointing at a map.
